## 1. 交付范围

在现有 New API 上完成统一账本、独立到期的积分包、多个额度窗口共同约束的订阅，以及可解释、可恢复的请求结算。复用已有用户、渠道、支付、模型适配和计价能力。

用户最终可以查看套餐有效期、各额度窗口、积分包余额及到期时间、请求扣款来源与用量依据。管理员可以配置套餐和积分有效期，管理权益标签，处理有依据的账单调整。

改造跨越数据库模型、结算服务、管理接口、Redis 缓存和前端，属于中到大型账务改造。现阶段按里程碑安排，不承诺缺少业务决策和完整测试基线支撑的日历工期；P0 完成后按实际任务拆分估算。

具体资源产品、自动续费/自动升级、新供应商适配、完整运营活动系统、跨用户转赠、用户欠款、自动现金退款和历史用户商业迁移不在本计划交付范围。已有签到、邀请奖励等发放入口必须接入新账本。

### 1.1 协议与兼容范围

- 首批完整链路验收覆盖 OpenAI Chat Completions、Responses、Claude Messages 的文本请求，包含流式和非流式、输入输出与缓存计量。
- 图片、音频、实时会话、异步视频和任务插件等已有收费路径纳入钱包入口盘点与兼容回归，沿用各自计量语义，不套用文本估算规则。
- 新账户只允许使用已验证接入新账本的路径。尚未验证的路径应在消费前明确拒绝，不能回落到旧余额扣款；首批对外开放的模型和协议清单在 P0 记录，缩减目标范围需另行确认。
- `relaykit/` 继续只负责协议类型和转换；账户、数据库和结算规则放在主模块。

路由调查和页面契约可以提前开展；生产账务切换必须等到相关阶段共同验收。P1 建表时就验证迁移，P6 再演练完整发布流程。

开发验收采用逐步接通的真实链路：先“发包 → 文本请求预占 → 用量结算 → 包明细查询”，再加入“多窗口订阅 → 同一请求结算”，最后补偿和恢复。每条链路通过后再扩展入口，不等到 P5 才首次验证真实请求；页面可先使用现有入口或管理 API 验证。

### 2.1 开发轮次估计

按当前设计，安排 **12 轮开发与验收，并预留 2 轮处理回归和迁移问题**。全部完成按 12–14 轮规划；这是当前范围的工程估计，不是工期承诺。P0–P6 是能力阶段，轮次是能独立检查和提交的工作批次，一个阶段可以分多轮完成。

一轮包含明确契约、失败测试、实现、受影响回归和结果审查，可能需要多次对话和多个提交。代码写完但必要数据库验证、业务规则或恢复用例尚未完成时，该轮仍未验收。这里的“全部完成”指本计划范围及 A01–A24 验收完成，包含迁移与发布准备；生产部署按实际发布安排执行。

| 轮次 | 对应阶段 | 本轮交付与验收重点 |
| --- | --- | --- |
| 第 1 轮 | P0 | 收支与协议清单、完整测试基线、三数据库/Redis 环境与 CI 矩阵；确认第 2–4 轮依赖的规则 |
| 第 2 轮 | P1 | 积分包、账务记录及数据库约束；发放、防重、到期、用途筛选、跨包分配和并发守恒 |
| 第 3 轮 | P1、P2 | 持久化请求、预占/结算/释放，接通一个真实文本请求链路；关闭信任旁路，核对 Key 额度和包明细 |
| 第 4 轮 | P2 | 全部充值、兑换、签到、邀请、转入和管理员调整；商品发放/撤销与操作核查，退款付款不在系统内执行 |
| 第 5 轮 | P2 | 图片、音频、实时和异步任务等已有收费入口接入，按首轮清单验收；预占追加、退款与分步失败处理 |
| 第 6 轮 | P2 | 恢复接管、执行代次、迟到提交、独立日志库待办及账户核账；故障后从持久化状态恢复，补齐 P1/P2 验收 |
| 第 7 轮 | P3 | 套餐版本、锁价订单、连续 30 天有效期、标签快照、余额购套餐；购买快照、续费顺延、管理员取消权益；不自动退购买款 |
| 第 8 轮 | P3 | 多窗口联合限制、首次使用启动、多 Key 共享、旧代次结算、续费及订阅/积分编排；完成 P3 验收 |
| 第 9 轮 | P4 | 字段级用量证据、价格与估算版本、重试/断流费用、原账单补差、未知与平台未收取费用处理，完成计费解释链路 |
| 第 10 轮 | P5 | 负载均衡、账号级固定、会话隔离、凭证轮换和重试阶段验证；补齐路由配置及记录的缺口 |
| 第 11 轮 | P5 | 管理/用户页面、包和窗口明细、参考价与实际扣款展示、标签失效、多语言与真实浏览器链路 |

每轮同时交付自己的接口契约和必要测试。第 3 轮已有完整消费链路，第 7–8 轮加入订阅链路，第 11 轮形成完整使用界面，第 12 轮满足整体交付条件。必要的防重与恢复状态从第 2–3 轮就建立，第 6 轮集中做跨进程恢复验收；任何一轮单独完成都不作为生产账务切换依据。

本估计假设 D01–D12 在对应轮次前确定、测试环境可用、已有协议和付款渠道按当前范围复用。若改变额度量纲、改成严格滚动窗口、扩大商品退款自动化范围，或开发数据出现结构兼容问题，需依据新增失败案例重排轮次；不能删掉三数据库、故障恢复或迁移验证来维持数字。

第 1 轮结束时复核轮次，之后每轮只根据实际新增范围和验收结果调整。全部验收提前完成则不强行使用预留轮次；预留用完仍有必要验收未通过时，继续处理并如实更新计划。

### 4.2 数据约束

模型最少需要表达以下信息；建表时确定 GORM 字段、索引长度和跨数据库约束，不能仅凭此表声称数据库兼容。

| 记录 | 必要字段与约束 |
| --- | --- |
| 积分包 | 用户、来源类型及业务 ID、发放量、生效/到期时间、余额分量；来源事件防重复，按用户和到期时间查询 |
| 请求账单 | 服务端生成的逻辑请求 ID、用户、价格及商品规则快照、结算状态；同一次网关内部重试复用 ID；区分参考计价、窗口用量和实际积分扣款 |
| 账务操作 | 请求或发放事件、操作类型、操作 ID、输入摘要、结果；唯一操作重复调用返回原结果，不同输入复用同一 ID 应拒绝 |
| 预占分配 | 操作、积分包或窗口代次、预占/结算/释放量；能逐笔回溯，不通过当前余额猜来源 |
| 套餐版本与订阅 | 不可变规则版本、锁价订单、付款成功时间、有效期、标签快照及终止关联；同一订单不重复开通 |
| 窗口实例 | 订阅、规则、代次、起止、上限、已结算与预占量；同一有效代次不得因并发请求重复创建 |
| 上游尝试与证据 | 逻辑请求、尝试序号、内部账号标识、结束原因、字段级用量来源、用户费用和上游成本；不保存可用凭证 |
| 执行资格与恢复待办 | 所有者、租约、执行代次及未完成步骤；条件更新取得资格，迟到旧执行者不能提交 |
| 购买退款与权益撤销 | 原订单、防重退款 ID、管理员操作依据、关联包/订阅、已用和预占处理；保留历史不直接删账 |

积分使用有边界的整数，金额换算复用 [common/quota_math.go](../../common/quota_math.go)；不通过浮点累计积分。时间统一保存为服务端 UTC 时间戳，窗口比较采用左闭右开；页面按用户时区显示。

同一业务操作涉及的账本、来源分配和窗口修改尽量在主数据库同一短事务中完成。各步骤按固定顺序取得账户与来源的并发控制；MySQL/PostgreSQL 使用现有 `lockForUpdate`，SQLite 采用能经并发测试验证的事务与条件更新。外部请求不置于长事务内。

新账本启用后，`user.quota` 和 Redis 只能作为兼容汇总或缓存，不能在账本失败时充当另一份可独立消费的余额。过期会使缓存失真，因此准入必须核实有效期和权威余额；缓存失效可重建，不能恢复已被占用或已到期的额度。

关闭新账户的大余额信任旁路；无限额 API Key 不免除用户账本和套餐窗口检查。窗口单位与包积分分别表示，依据[账户核账规则](../design/accounting.md#3-必须保持的正确性)核对所有分量，平台未收取费用独立记录，不扣成负包。请求与账户分别存储规则版本及并发版本，避免把商品版本与执行资格混为一项。

### 4.3 接口与状态约定

内部按发放、预占、追加预占、结算、释放、调整六种业务操作组织。入口接收稳定业务 ID、用户、规则快照及必要数量；返回持久化结果和来源明细。客户端随意提交的请求 ID 不直接作为跨用户防重依据；客户端重新发送是否为同一业务调用需单独定义，不能和网关内部重试混同。

请求至少区分已创建、已预占、执行中、待结算、已结算、已释放、待核查。超时扫描只负责找出未完成操作；没有费用依据时不能直接全退。后续调整关联原账单，以新增操作保存，原始证据不覆盖。

| 管理能力 | 接口安排 |
| --- | --- |
| 套餐编辑、购买、查看订阅 | 扩展现有 `/api/subscription` 路由下接口，增加版本、窗口和标签；旧字段兼容规则在 P3 写入接口测试 |
| 用户积分包与账务明细 | 在现有用户 self 路由下新增查询接口，返回分页、包有效期、可用/预占等分量和服务器时间 |
| 用户窗口与权益查询 | 自助查询返回窗口起止、上限、已用、预占、可用及权益失效时间；后端过滤无效权益 |
| 管理员发放和调整 | 新增有权限校验的变更接口，要求原因和防重操作 ID；禁止任意覆盖一个总余额 |
| 请求账单 | 扩展现有使用记录查询，关联用量来源、实际扣款包、窗口代次与调整；供应商成本和内部账号仅管理员可见 |

新增接口的最终路径、字段和错误码在所属阶段实施前写入仓库现有 OpenAPI 文档及契约测试。错误至少区分窗口不足、积分不足、权益到期、参数冲突和账务待处理；沿用现有 API 响应外形，页面不能把业务失败展示为成功。

### 4.5 已实现的积分包核心契约

第 2 轮的 `model/credit_pack.go` 提供以下内部接口。它们接受可信服务器时间，尚不直接暴露给客户端，也不自动启用新账务账户。

- `GrantCreditPack(db, CreditGrant, now)` / Tx 版本：用户必须存在；来源类型 1–32 字节、来源业务 ID 1–128 字节且非全空白；正整数积分不超过 `common.MaxWalletQuota`；生效早于到期，时间为正且 JavaScript 安全整数。用途必须明确选择 API（1）、购买订阅（2）或两者（3）；各来源用途和期限由管理员显式配置。
- `ReserveCreditPacks(db, CreditReserve, now)` / Tx 版本：请求 ID 非空且不超过 128 字节；金额为 0 到上述上限；单次用途为 API 或购买订阅。按到期、发放时间、ID 升序分配；不足或任一步写入失败时全部回滚。
- `ListCreditPacks(db, userID, now)`：内部账户查询投影；包到期的未分配量展示为失效，预占保留，未来生效量仍属未分配。后续公开 API 必须分页并提供可消费状态，不能将投影对象保存回表。
- 发放以用户和来源事件防重，预占以用户和服务端逻辑请求防重。稳定 ID 的摘要与输入摘要分别存储；相同输入重放返回原提交结果，数量或规则变化返回 `ErrCreditOperationConflict`。返回值是原操作快照，当前状态另查包，不拿历史快照当余额。
- 每个包保持 `Issued = Available + Held + Spent + Expired + Revoked`，各分量非负且有界；未到期未分配量和全部预占量合计受钱包上限约束。账户行写锁先于读包，SQLite 也以条件写入取得写事务；所有包变更参与同一串行点，不依赖 Redis 锁。
- 本轮表约束保护操作、分配、流水的唯一性和字段非空；数量/守恒由受控事务验证，不依赖 MySQL 5.7 不执行的 CHECK。迁移只加表，旧总余额保留，不伪造旧包历史。

预占不代表已经消费。第 3 轮补齐如下生命周期；发放入口、途中追加预占、调整、撤销与到期登记在后续轮次完成，业务冲突或余额不足不能回落为旧钱包扣款。

### 4.6 已实现的请求结算契约

- `User.AccountingVersion`：0 为旧模式，1 为新积分模式。数据库迁移保留旧用户为 0；单有积分账户或包不启用新模式。本项目从新部署开始，不开发历史用户切换工具；新账户启用契约和防旁路由第 12 轮完整验收。
- `BeginCreditRequest`：主库同一事务写入服务端请求 ID、初始价格/表达式快照、来源预占及 Key 额度。请求费用沿用单次 `MaxQuota` 上限。主库读取 Key 的真实归属和无限额标识；无限额只解除 Key 上限，不能跳过积分包检查。大旧余额、缓存和零预估都不能绕过新模式；合法余额不足时拒绝新付费请求，平台未收取费用不阻断有新资源的使用，明确免费请求仍可记录。
- `MarkCreditRequestSubmitted`：发出上游请求前持久化提交标记；写入失败时不发送。当前接通 OpenAI、Anthropic 的 HTTP 文本入口（Chat/Completions、Responses、Claude Messages）；图片、音频、实时、异步及其他运输方式尚未接入时先拒绝。只用订阅、订阅优先且已有订阅的账户不会被静默改成积分付款，等待第 8 轮接通订阅。
- `FinishCreditRequest`：先在短事务中保存唯一结算/释放意图，再在资金事务中完成来源和 Key 调整。资金写入失败留下 `pending` 及原预占；重启后可重放同一意图。结算与释放互斥，改变结果或费用的重放返回冲突。同金额结算也必须关闭持久化预占，不能因差额为零跳过。
- 原预占按原 FEFO 顺序结算；到期后的未用量归入失效，仍有效则返回原包。实际费用超过预占时，以当时合法来源和有限额 Key 的剩余量补扣，剩余不足由平台承担。包、有限额 Key 均不透支；请求保留 `Actual/Charged/Uncollected`，用户用量统计和收费日志记录真正扣款，参考费用另列。
- 充值只发放本次积分，不偿付以前的平台未收取费用。撤除旧 `CreditDebt` 与自动偿付代码，补余额不足、超预占、Key 上限、充值不追扣、防重及核账用例。此项按 2026-10-08 最新 D07 在需求校正轮补完，不把需求变化记作原设计的 bug。
- 未发送请求可以释放。已发送但结果不明、非明确免费且实际为零的请求保留预占并标为 `review`，不能当作零费用退款。字段级证据、合理的真正零费用、断流估算、恢复工作器和独立日志待办分别在第 9、6 轮补齐；本轮不声称全部证据计费已完成。
- 价格快照记录初始预估规则，不改变现有表达式及自动分组重试语义；实际尝试的路由、价格和用量证据由第 9–10 轮补齐。查询、恢复、调整只能通过受控事务，不能直接保存查询投影或覆盖余额。

### 4.7 第 4 轮发放与退款核查契约

本轮针对新积分账户接入现有发放入口；旧账户保持旧行为，通用用户编辑不能修改账户模式或覆盖新账务余额。新账户的管理员增减/覆盖旧接口明确拒绝；正向调整通过限时发包，购买撤销通过人工核查入口保留来源，终局扣回按 D12 确认后执行。

| 来源 | 稳定事件 | 主库原子边界与期限依据 |
| --- | --- | --- |
| Epay、Stripe、Creem、Waffo、Waffo Pancake、人工补单 | 充值订单 ID | 下单保存积分数量、期限、用途快照；完成订单与发包一起提交，充值不偿付平台未收取费用；回调重放只产生一次发放 |
| 兑换 | 兑换码 ID | 代码已使用标记与发包同事务；创建时保存独立积分期限/用途，旧码无快照时必须有明确来源策略；已用代码不可改写或重新启用 |
| 签到 | 签到记录 ID，用户/日期唯一 | 签到记录与积分包/流水同事务；零奖励只记录签到；配置的随机范围先校验，资金失败不留下签到成功记录 |
| 注册、被邀请、邀请人 | 被创建用户 ID，分别带来源类型 | 用户创建与新模式各奖励同事务，OAuth 后处理重放不再发钱；来源策略给出期限和用途；后处理日志不作为资金事实 |
| 管理员/运营补偿 | 管理员填写的事件 ID | 记录真实操作者、原因、明确生效/到期/用途；同事件同输入重放安全，改变数量等输入返回冲突 |

`CreditSourcePolicy` 以来源、正期限、用途和递增版本配置。策略更新必须携带 `expected_revision`，旧版本不覆盖新设置。未确认的默认期限和默认用途不自动填入；具体策略选项及答复状态在产品设计 §7.6。充值积分有效期从本次成功发放开始；月订阅核验付款时刻的规则在第 7 轮实现，不能把这两种时间混为一谈。不同商品的独立策略配置和页面由后续商品/管理轮次扩展。

订单完成先锁定订单状态，SQLite 在读状态前取得写事务，MySQL/PostgreSQL 使用项目统一行锁；发包仍使用账户串行点。Ledger/pack/order 任一步写入失败全部回滚，重试不重发。旧 Scalar 余额和其缓存不会成为新包的第二笔钱。

邀请奖励在新模式直接形成有期限包，不新增领取商品步骤。旧 `AffQuota` 转入接口对新模式拒绝，避免凭空续期；本项目无历史用户迁移。明确禁止跨用户转赠和转账。

退款核查：`OpenCreditReviewCase` 在同一账户事务冻结包的新使用并保存案件；不抹去可用量、已用量、原预占或来源流水。原请求仍可结算其预占。`RecordCreditCashOutcome` 保存追加式现金证据及案件当前状态：相同内容重放不覆盖后来的确认；不同终局结果冲突；未知结果可补充核实。确认必须有外部参考和证据。它不调用支付平台退款、不发现金、不自动扣回或解冻积分；管理员可取消权益，不自动退款或返还商品购买款。已有现金结果仅作为外部处理依据记录，不承接付款或自动补发。

管理 API 与 OpenAPI 记录保持一致：

| 路径/方法 | 角色与 PAT 权限 | 行为 |
| --- | --- | --- |
| `/api/credit/admin/policies` GET/PUT | Root，`option:read` / `option:write` | 读取/按版本配置来源策略 |
| `/api/credit/admin/grants` POST | Admin，`billing:write` | 发放限时包 |
| `/api/credit/admin/reviews` GET/POST | Admin，`billing:read` / `billing:write` | 指定用户分页查询/创建核查 |
| `/api/credit/admin/reviews/cash-outcome` POST | Admin，`billing:write` | 记录已核实现金结果 |

非 Root 管理员只可操作比自身角色低的目标；服务端按主库当前角色、启用状态及包/案件归属再次校验。操作者从已认证身份取得，客户端 `actor_id` 不改变操作者。写操作沿既有 AdminAuth/RootAuth 管理审计及 CriticalRateLimit；面板鉴权使用 Authorization Bearer，刷新 Cookie 不作为这些接口的独立授权。非法输入 400、未认证 401、无权限 403、不存在 404、防重或版本冲突 409、存储错误 500；内部存储错误不返回数据库细节。

本轮权限检查依据 [OWASP ASVS 5.0.0 V8](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x17-V8-Authorization.md) 的 8.1.1、8.2.1–8.2.3、8.3.1–8.3.2，以及 [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 指南。测试验证读写权限分离、过期/撤销、角色降级、伪造操作者、目标归属及重放；这是所改接口的验证记录，不宣称整个项目完成 ASVS 认证。

### 4.8 第 5 轮追加预占与多协议契约

追加预占按请求累计目标额执行，同一目标重放不重复占用。账户、积分包、请求累计额、追加来源记录和 Key 额度在主库同一事务提交；不足时全部回滚。追加只使用追加时合法来源，已过期可用量不能补占。各次预占的原来源记录保持不可变，结算按预占取得顺序消费，剩余返还仍遵守原包期限。第 3 轮没有追加记录的在途请求保留原预占，并在第一次追加时补齐来源关联。

每个协议在开启新账户访问前必须具备发送前的持久化标记和唯一结算入口；不能只删除协议限制便宣称接入完成。图片参数覆盖后先追加再发送，实际数量沿用项目图片载荷计数规则。音频、实时累计用量、异步任务成功/失败及持久化失败逐项验证，异步任务需要持久化关联原请求，不能在轮询时直接改旧钱包。

任务与账单同事务保存关联：原任务编号、区分大小写的摘要、任务表主键、用户和任务类型。完成时重新锁定并核对原任务，主库金额回写与包、Key、请求状态共同提交。任务失败但费用未知时保留预占进入核查，不按失败状态自动全退。实时计量由单个处理循环维护，去重有稳定事件 ID 的完成回执，音频/文本/缓存沿表达式归一化；Responses WebSocket 的复用连接每个请求仍独立标记提交。

中断与失败行为参考 New API，核对结果和改造边界见设计 §8.1。可核实成功消费和资金一致性不依赖上线配置，使用本地三数据库和模拟上游验证。

### 4.9 第 6 轮恢复与核账契约

执行资格属于单个请求，包含服务器生成的所有者、递增代次及租约截止。主库账户锁内取得或续租，活跃租约不得被另一执行者抢走；到期后新代次接管，旧代次的发送、追加、结算、释放及核查写入均拒绝。正常长请求定时续租，租约丢失时取消本地请求；租约不是上游停止或免费凭据。异步提交交接后释放执行资格，后续轮询取得新资格。

恢复分页扫描持久化记录：已有终结意图只重试原意图；未提交请求可释放；已提交且结果不明只转核查；异步任务先按已保存任务状态处理，不能凭超时推算收费。错误、重试次数和下次时间可查询，不删除资金或防重事实。扫描和账务提交均允许多实例竞争。

恢复默认每 30 秒扫描，`CREDIT_RECOVERY_INTERVAL_SECONDS` 可调整；`CREDIT_RECOVERY_MAX_ATTEMPTS` 默认 20 次，超限保存待处理标记，不清除原意图或资金。具体重试错误在主库和管理查询可见。`POST /api/credit/admin/work/retry` 要求 `billing:write`、唯一事件及原因，只重试已知意图或日志；不知道费用的请求不能通过“重试”按钮变成退款或收费。`GET /api/credit/admin/work?user_id=…`、`GET /api/credit/admin/reconcile?user_id=…` 要求当前管理员及 `billing:read`，不返回租约所有者或日志载荷。权限控制复用主库目标角色校验；参照 [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 与 ASVS v5.0.0 V8，验证拒绝默认权限、读写范围及角色降级。

结算主事务更新用户/渠道统计并创建独立日志待办，重放不重复统计。日志库独立事务保存投递标识和日志，响应丢失后查同一标识，不再重复插入；主库待办完成失败只重试确认。非事务日志引擎必须有经过验证的等价防重能力才能自动投递，否则保留可见待办，不冒充成功。核账按一致事务快照核对包守恒、流水分量、预占与分配、请求实际扣款及平台未收取费用，返回具体记录和差量，禁止自动改余额抹平差异。

### 4.10 第 7 轮套餐版本基础契约（已实现）

版本发布保存管理员显式确认的不可变套餐记录；发布本身不发放权益。实际购买依据锁定版本开通，不改旧订单或旧订阅。沿用现有套餐草稿，保存完整服务端快照、摘要、六位小数售价整数、币种、连续 30 天规则、发布人、时间及唯一事件。版本不使用客户端提供的支付结果。

发布请求明确套餐 ID、已看到的草稿摘要、上一版本号和唯一事件；版本号省略或 null 与显式 0 区分。主库锁定套餐后读取当前草稿，草稿已修改或版本已更新则返回冲突，不覆盖其他人的操作。同一事件重放返回原版本，不因为之后编辑而发布不同合同；失败不留下版本或跳号。草稿读取绕过旧缓存。管理员身份取当前主库角色和状态，接口要求 billing 读写范围，客户端不能选择操作者。分页拒绝负数及偏移溢出；适用权限控制参照 §4.9 的 OWASP 指引与 ASVS v5.0.0 V8。基础能力采用当前已经确认的月套餐连续 30 天规则；其他期限不在这里偷偷换算。

`GET /api/subscription/admin/plans/:id/versions` 返回当前草稿摘要、最新版本号和分页版本；`POST` 发布版本。购买、标签快照、续费和管理员取消按设计 §7.7 实施；多窗口消费在第 8 轮接入；第 7 轮实现与验证见开发进度。

订单与支付事实基础沿用账户设计 §8.3 的约束：主库先保存当前已发布版本、完整合同、整数金额和币种；下单事件按用户防重。基础模型接受服务器明确期限；四种现金入口统一使用从下单开始的一小时付款期限；重复下单返回原合同，修改草稿不修改已存在订单。新下单必须指向当前发布版本并检查当前上架状态。购买分别通过下述余额或现金适配入口开通权益。

支付事实只能由完成验签及支付核查的服务端调用方写入，无客户端“付款成功”入口。保存渠道、稳定事件/交易编号、实际付款人、金额、币种、付款时间及取证来源与摘要，未知量保持未知。缺失事实、金额/币种不符、付款早于订单、付款不在订单期限内及交易已归另一订单均进入可见核查；不把回调接收时间充作付款时间，不根据订单售价猜到账金额。重复事件返回原事实，同事件不同内容拒绝，同时按内容防重追加关联原回执的矛盾观察，与当前订单核查标记一起提交；冲突结果在保存成功后返回，不能因事务回滚抹去核查依据。不同事件的同一交易不能归两份订单。核验成功与权益发放分开，异常记录不被之后的正常通知自动抹掉。开通、续费、标签及管理员取消按已确认的设计 §7.7 执行；不提供商品自动退款。

支付日志只记录处理阶段、订单/事件标识与必要请求位置，不打印签名、支付链接令牌、完整正文或查询串。适用 [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 的敏感数据排除与日志注入控制，以及 [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)；ASVS 版本沿 §4.9 的 v5.0.0。这里只验证受改支付路径，不宣称全项目完成认证。

已接通 Stripe、Epay、Creem、Waffo Pancake 四种原订阅渠道的版本化合同适配，详见 §4.12–4.14。取不到可靠付款事实时进入人工核查，不根据订单反推到账。税费、优惠、币种及精度须与合同一致，付款后不悄悄改价。验证使用本地签名与 SDK 网关，不要求生产账号，也不声称生产商户已联调。

### 4.11 第 7 轮购买期限与余额接口契约（已实现）

同套餐续费形成连续期限段，新增段从已有链的到期时刻开始；每段保留购买版本、额度、标签和价格，不提前增加当前额度。首次合同从已核实付款时刻开始、持续 30 天；回调延迟不把付款时刻改为收到通知的时间。用户当前权益只查询已生效段，`renewal_end_time` 显示已付款的整条链到期时间。

标签采用字符串键值表，最多 32 项，键不为空且最多 128 字节、值最多 2048 字节。发布和管理写入均校验；修改草稿不改已购买标签。标签本身不授予外部权限。

`GET /api/subscription/plans` 对新账务账户返回可购买的最新已发布合同和 `version_id`，不把未发布草稿价格或网关 SKU 暴露给购买者。新账务账户使用 `POST /api/subscription/balance/pay`，提交 `version_id`、唯一 `event_id`；用户身份仅来自登录，客户端不能指定付款成功或买家。价格按合同的 USD 六位小数金额、当前 New API 费用积分单位换算并向上取整一次，结果与单位在订单锁定；明确允许余额购买且币种为 USD 才支持这条入口，其他币种不能猜汇率。扣款按允许购买套餐用途的包先到期先用，订单、来源分配、付款事实和权益同事务提交；失败全部回滚。重放返回原权益，不重新换算或加 30 天。现金渠道见 §4.12–4.14。

`GET /api/subscription/self` 的 `current_rights` 返回当前生效快照；提前续费段仅在历史/期限记录显示，不提前授权。内部合同和网关商品标识不通过当前权益返回。数据库读取失败明确报错，不以空权益冒充成功。

`POST /api/subscription/admin/user_subscriptions/:id/invalidate` 取消新订阅需要唯一事件及原因，操作者取当前主库管理员身份，并验证目标用户权限。一次取消停止这条链的当前及提前续费段，保留原合同日期、付款与扣款来源，不发退款积分；取消前尚未开通的同套餐订单标记核查，迟到通知不能复活权益。已终止历史链不能影响之后的新购买，旧删除/重置入口不得改写新订阅。多窗口计量及期限切换在第 8 轮统一实现。


### 4.12 Stripe 版本化单次购买（已实现）

新模式的 `POST /api/subscription/stripe/pay` 接收 `version_id`、`event_id`；用户身份取认证上下文，金额和币种取已发布合同。先提交锁价订单，一小时付款期限保留于订单，重试不改期限；使用原订单号作 Stripe idempotency key。每次购买付一次款、开通或顺延 30 天，不启用后台自动续扣。Stripe Checkout 用单次 `payment` 模式、精确的 USD/CNY 分价格、自动创建发票，并把订单/付款人绑定元数据传入会话及发票。不支持的币种或不能精确换算成分的价格拒绝拉起支付，不悄悄四舍五入。

已验签的完成/异步成功通知调用服务端 Stripe API 查会话和发票，核实订单归属、付款人、支付状态、发票/会话客户一致、金额与币种。真实付款时间来自 [`invoice.status_transitions.paid_at`](https://docs.stripe.com/api/invoices/object)，通知创建或接收时间不用作付款时间。缺发票、缺时间或核验不符保存核查事实，不发权益。查询或存储失败返回 500 要求渠道重试；事实已保存但权益写入失败时，重试返回同事实并完成一次开通。原钱包 SKU 开关仅控制旧钱包回调，新套餐仍要求支付配置和验签，不依赖钱包商品。

安全控制：按 [Stripe 官方验签与重试规则](https://docs.stripe.com/webhooks)验证原始正文、签名及 SDK 默认时间容差；客户端没有成功断言入口；稳定事件和交易唯一约束防重复发放；审计不包含签名、支付正文、客户邮箱或链接令牌。沿用 §4.10 的 OWASP ASVS 5.0.0 身份/对象授权边界，不以已有旧路径代替验证。真实签名、本地 SDK 查询、缺事实、错归属、查询重试和开通失败行为测试已运行；第 7 轮最终快照已通过严格三库、全量、race、升级与重复启动验证，证据见开发进度。


### 4.13 Epay / Creem 版本化购买与结账防重（已实现）

两个入口均接收 `version_id`、`event_id` 并以认证用户创建锁价订单；旧模式仍用旧 DTO。Epay 另收 `payment_method`，目前只接受 CNY、精确到分的合同；协议没有提供汇率合同，不把 USD 数字直接当人民币。签名的商户订单号绑定已认证购买人，核对商户编号、金额、实际交易编号；浏览器返回与通知使用同一付款事实。原回执未提供可靠付款时间，保持 NULL / 核查，返回页显示 pending，不能显示权益已开通。原 SDK 的 MD5 支付协议没有在本轮升级，不能据此声称完整 ASVS 密码学合规；此观察不会自动发放权益。

Creem 查验原合同的商品 ID、环境、币种、onetime 类型和 inclusive 税费模式，再以锁定分价格 `custom_price`、数量 1 创建付款页；不沿用全局展示币种。身份绑定元数据由服务端生成；回调必须 HMAC 验签，旧测试模式的验签跳过不能写新购买事实。`amount_paid` 为可空整数，缺失与显式 0 区分；实际交易编号来自 `transaction`。创建/更新时间不是已证实的付款时间，保持核查，不自动开通。字段含义参考 [Creem 创建 Checkout](https://docs.creem.io/api-reference/endpoint/create-checkout)、[商品查询](https://docs.creem.io/api-reference/endpoint/get-product)及 §4.10 的交易字段。

`SubscriptionPurchaseOrder.checkout_state` 取空、started、ready、unknown，另保存输入摘要、渠道 checkout_id 和服务器响应。响应包含支付链接，只能在经过用户所有权检查的购买重放中返回；模型直接 JSON 不输出 checkout_response / 摘要。账户锁仲裁同订单的发起，两个独立 SQL 事务只有一个获得发送资格。started 未确认状态不能再发起；ready 原样返回已保存响应；unknown 保留核查。商品只读查询失败留在空状态，允许重试；创建已发送且结果不明时保存 unknown，不猜测外部失败。保存返回结果与权益激活是不同操作，即使发起期间管理员取消，仍保存渠道响应作审计，不开放新使用。

版本化购买、支付核查 API 和 CNY 草稿币种已实现，旧订阅创建/预扣拒绝新账务账户，旧增减/重置/删除拒绝版本化权益。未来预付期与窗口生命周期由第 8 轮接通。付款核查不能执行系统现金退款，也不能因后来收到普通正常通知就抹去历史冲突或管理员取消。


### 4.14 Waffo Pancake 与人工付款核查（已实现）

Pancake 新购买沿用已有一次性商品和认证结账 SDK，持久化订单后查验同 Store 的已启用一次性商品，再进入 started；不允许供应商循环订阅替代本站的 30 天购买期。发起金额采用 USD、精确到分的合同快照，不读取后来改动的草稿或钱包商品。SDK 并行创建付款会话和买家令牌，两者部分成功仍属于不明结果，保存 unknown 并禁止重复发起；短期 SDK 防重不能代替本地持久化发起状态。只保存不含买家 JWT 的现金会话响应，经过原用户所有权与账户/订单当前状态检查后才返回付款链接；每次 ready 重试单独获取新的买家令牌，不重新创建现金会话。令牌不持久化，不在订单列表、核查详情、审计或 SQL 故障追踪中输出。安装的 SDK v0.3.1 会给 Auth 请求生成可被缓存 24 小时的固定防重键，宿主只对认证端点移除该键，保留现金创建的原协议，并拒绝缺失、格式错误或已过期的令牌；网络请求完成后再次检查账户/订单资格。当前协议参见[官方 Auth 和防重约定](https://github.com/waffo-com/waffo-pancake-sdk-go/blob/main/docs/api-reference.md#auth)。

签名仍由安装的 SDK 进行 RSA 验证；宿主补齐当前协议的过去 45 分钟、未来 1 分钟时间限制，不能关闭时间校验。供应商重试复用首次签名，稳定通知 ID 和实际交易编号分别防重。`chargedAmount` 才是实际收款，缺失保持 NULL，显式 0 保留为 0；`amount`、`total`、`subtotal` 和税费报价不能补造收款事实。`paymentDate` 只有日期时不猜测时区或零点；只有完整带时区付款时间才能用于自动开通，否则进入人工核查。通知时间不能代替实际付款时间。依据：[供应商付款字段](https://github.com/waffo-com/waffo-pancake-sdk-go/blob/main/docs/webhook-guide.md#event-payload)、[重试与签名窗口](https://github.com/waffo-com/waffo-pancake-sdk-go/blob/main/webhooks.go)。本地 SDK 签名和现金接口验证使用测试密钥及模拟网关，不能宣称真实商户环境已经联调。

用户只读 `/api/subscription/orders` 和 `/orders/:id`，身份来自认证上下文；分页上限 100，页码乘法溢出拒绝，跨用户详情返回 404。输出合同价格、期限、支付和核查状态，不输出内部合同、渠道 SKU、链接令牌或管理员证据。管理员用 billing:read 查询 `/api/subscription/admin/payment-reviews` 和 `/orders/:id`；普通管理员不得读取同级及以上账户，Root 按原权限管理。事实详情有界分页，并返回真实显示的最新事实和 `latest_fact_id`。

管理员通过 billing:write 的 `/api/subscription/admin/orders/:id/reconcile` 补齐外部已核验收款：必须明确提供 `expected_fact_id`（没有事实为 0）、操作事件、实际交易编号、百万分之一币种单位金额、币种、准确付款时刻、外部凭证引用和原因。路径决定订单、认证决定操作者，正文不能伪造二者。金额/币种须等于锁价合同，付款时刻须在原订单付款期限内；相同交易不能归属另一个订单。持有账户和订单锁后重新读取最新事实，不接受过时核查结论。

核查确认追加一份 `admin.manual_evidence` 事实和带操作者、原因、凭证引用的操作记录，原供应商事实不改。事实、解除核查和权益开通原子提交，开通失败可重试且不留下半次批准；相同事件返回原结果，改输入冲突。started/unknown 也可凭外部证据确认收款，不能因此重新调用现金创建接口。独立 `rights_cancelled_at` 保存管理员取消边界，后到回执改变核查原因也不能解除它；取消后的订单不允许通过核查重新开通。系统不执行现金退款、不退购买积分、不记用户欠款。此入口不修改已确认的其他交易或已购买时间，需要变更商业处理时由管理员在系统外处理现金。

草稿创建/修改保留提供的币种（规范化大写、空值仍默认 USD），不再强制覆盖成 USD；发布采用同一币种校验。购买渠道分别检查自身支持币种，不能靠展示币种或隐含汇率改变合同。

### 4.15 第 8 轮窗口消费契约

已发布合同新增 `window_rules`：最多 8 个小写 ASCII 稳定 ID（字母、数字、下划线或连字符，最长 32 字节，保留 term）、周期秒数（正且不超过 30 天）和正费用积分上限。版本化合同只接受旧 `quota_reset_period` 为空或 never，其他旧单计数器重置须改用明确窗口规则后发布，不能静默忽略。默认无短窗口，套餐 `total_amount=0` 沿用无限累计额度。每个购买期限有固定 term 窗口，短周期首次提交上游时确认起点；提前续费不创建或重置当前期限的窗口，未来期限到开始时使用自己的购买快照。

请求在账户锁下按原四种偏好选择整笔来源，持久化 funding_source/subscription_id。订阅优先按已生效期限结束时间、ID 选择，所有生效合同均允许接续时才自动改用钱包，沿用现有严格合同约束；wallet_only/wallet_first 是明确选择独立钱包。钱包与窗口不拼单。所有适用窗口和 Key 同事务预占，不足无部分写入；免费请求不启动付费窗口，仍检查当前用户状态及 Key 停用/到期；付费零估算不能绕过已耗尽 Key。候选窗口协调并发预占，首次提交确认，未提交且该代无其他占用或消费时释放作废候选；另一请求使用后不得作废。

预占分配固定保存窗口代次。追加仍检查原期限和原代次，结束后不能用新代次补占；结算可使用原预占，剩余额度补扣须仍合法有效且 Key 允许，超出记录平台未收取量，不转到钱包、不记欠款。每个适用窗口记录同一用量，但 Key 和用户计费只计算一次。未知用量保留预占及现有恢复资格，故障恢复继续同一来源和代次。relay 的 403 错误区分 subscription_window_insufficient、subscription_rights_unavailable 与原 insufficient_user_quota，均跳过重试。用户 self 查询返回服务端时间、有效权益及窗口状态；内部 BillingSession 仍用既有持久账务包装器入口名 credit_packs（复用任务路径），账单 funding_source 及消费日志记录真实 subscription_windows/credit_packs，不能据包装器名称二次扣旧订阅。规则详情与故障断点按现有验收场景 S07–S10 及 F01–F07 验证。

### 4.16 第 9 轮用量与账单修正契约（已实现）

在结算意图之前保存追加式用量证据，记录请求、尝试、唯一事件、序号、累计/增量、采集阶段及字段来源。每个费用项目区分 upstream（真实报告）、estimate（有算法版本的观察量估算）、adaptor（已有适配器归一化但来源无法进一步核实）、unknown（数量为 NULL）；明确零值不等于缺失。只保存用量片段和计价快照摘要，不保存对话、提示词或凭证。重复事件返回原记录，不同输入冲突，旧执行代次不能写证据。较早累计回执不能覆盖新事实，增量不得重复计入。

文本估算追加 `UsageEstimation`：计数版本、实际模型、方法、真实分词器名称及构建依赖版本、数值参数/开关和原本地数量。输入在 `EstimateRequestToken` / `CountRequestToken` 实际计数时捕获，随原价格快照保存；缺失终局输入复用这一捕获，不使用结束时的计数开关。输出按原适配器的映射后模型计数，保留独立选择的多段舍入和工具附加量。已核实终局不附加本地估算描述；途中下限高于本地估算时，字段数量保留下限，描述数量保留原本地估算。跨事件增量合计不附单个计数器描述，原不可变事件保留各自依据。描述仅允许 estimate 来源，字符串/映射长度和所有数值有界；旧事件缺少新描述仍可读取，不能凭当前程序补造旧版本。媒体合计及原计数算法版本记录于输入描述，逐项记录图片低细节/分块/分片参数、固定媒体估值及上传音频时长。最多保留 64 项细节，更多项目仍参与合计并明确 omitted_components 数量；不保存文件标识、地址或媒体内容。音频及实时的逐次算法依据和尝试价格版本见本节后续契约。构建信息缺失的依赖版本记录 unknown，不能硬编码假称已核实。

其他适配器仅返回归一化 DTO 时，保留缓存读写、媒体输入/输出及思考数量，来源明确为 adaptor、算法为 new-api-adaptor-normalized-v1；标量缺失/零不可区分时记 unknown，指针明确零仍保留。已有原字段事实优先，不被通用归一化覆盖；保留原 New API 的有效计费语义，不凭字段名补造供应商原量。

最终证据同时保存生成消费日志所需的计量明细，在同一主库事务关联账单；随后结算和 outbox 投影复用这份证据，崩溃恢复不能只剩金额。价格表达式/版本和换算依据沿用购买/请求快照；原始证据不被补差覆盖。真实零费用必须有依据才能释放已提交请求的占用，未知仍保留预占核查。

后续修正采用有权限的管理员追加事件、证据版本和原因，回溯原包/原窗口。调低只返还原实际扣款及原分配，到期部分计入失效；调高只增加参考计价及平台未收取量，不产生用户欠款、追扣后续充值或占用新窗口。重复和并发修正按当前版本防重，任何中途写入失败全部回滚。已实现接口及验证如下。

修正实现按一个不可变财务版本保存原请求、当前参考量、净扣款、未收取量、返还量和原分配变动，另保存独立日志投递状态。管理员身份由服务端取得并按主库重新校验，写入要求唯一事件、当前版本、证据版本及原因；相同事件重放返回原结果，不同内容或过时版本冲突。修正证据追加在 `adjustment` 阶段，不替换原终局证据关联。调低从最后扣除的原分配开始返还，以保留最早到期包的原消耗；含结算追加分配，不按当前包重新分配。过期包返入失效分量，已被阻止使用但尚未过期的包返入撤销分量。原分配、原账单、原日志均保留。调高不恢复已经退还的扣款，不占用新增积分；净扣款只可减少，差额计入平台未收取。窗口修正只指向原分配代次，多个窗口更新不重复返还 Key 或用户统计。已实现原分配核账、用户/管理员查询、独立 SQL 日志防重投递及有限次重试/人工恢复；SQLite/MySQL/PostgreSQL 行为、fresh/release 迁移和重复启动验证通过。最终证据见开发进度“第 9 轮最终交付”。

核账检查财务版本连续及净费用、修正操作结果、原价格摘要、管理员证据指纹与关联、原包/原窗口分配，以及对应返还流水。总余额正确但凭证或返还关联损坏同样报告差异。任务、Midjourney 的终局重放读取当前净扣款；通用任务回写不再拥有新账本的扣款字段，防止迟到的旧内存对象覆盖更正结果。Key 已删除不阻止原账户返还，账户及原来源仍须存在并满足数量约束。

授权验证参照 [OWASP ASVS 5.0.0 V8](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x17-V8-Authorization.md) 的 8.1.1–8.1.2、8.2.1–8.2.3、8.3.1–8.3.2 和 [Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。已验证读写 scope 分离、账户归属、忽略伪造操作人、缺少明确版本、降权后拒绝和用户字段隔离；不据此宣称整项目 ASVS 合规。

核查确认的实现契约：`CreditRequest.UsageEvidenceID` 继续关联原始终局；新增默认 0 的 `ReviewEvidenceID` 指向追加的 `review` 凭证。唯一 `bill_review` 操作保存操作人、外部参考、原因及确认内容，操作与凭证关联受指纹和原价格摘要约束。确认要求至少有一个来源为 upstream 或 adaptor 的完整数量；estimate、unknown 或部分数量不能作为人工确认依据。明确零费用必须提供零收费依据，不能靠未报告的零金额退款。当前有效租约阻止人工接管；确认提交递增执行代次并唤醒恢复，旧执行者不能迟到修改。原任务必须已经成功或失败，处理中任务拒绝确认；失败状态本身不证明费用为零。确认、证据和唤醒同一事务，后续资金结算继续原来源、原窗口和无欠款规则，失败可沿原确认恢复。自动任务回写不再拥有已人工确认账单的计量，也不能把确认重新撤回核查或改为释放。原终局和新确认都保留，管理员审计仅向管理员展示。已有金额意图的重试仍走恢复接口，已结算账单仍走修正接口；三者不能互相替代。当前阶段已通过三库行为、fresh/release 迁移及重复启动；后续新增结构仍需重新验证。序列化凭证和确认审计均限制为 TEXT 可存的 65535 字节，不能在 SQLite 接受、在 MySQL 才报保存失败。

确认后的资金事务失败时，待结算金额仍可查询；实扣和平台未收取量保持 0，完成结算后才确定，不能提前把尚未扣款认作欠款或平台成本。用户账单只显示人工确认标记和自己的费用；管理员账单额外显示确认依据，原价格及内部载荷仍隐藏。已持久化的合法确认不因操作人随后降权而失效，新确认和重放仍需当前授权。


当前实现边界：`CreditUsageEvidence` 保存不可变事件，唯一事件摘要及请求/尝试/阶段/序号分别防重。`GetCreditUsageProjection` 逐字段按序号合并：累计值覆盖此前增量，其后的增量只计一次，迟到事件不能按到达时间覆盖新累计值；不同尝试独立。最终 `CreditConsumeSnapshot` 保存参考金额、日志计量、流式标识和已有权限分层的日志元信息，事务关联请求，再保存金融意图；金融意图金额必须与最终证据一致。崩溃发生在证据提交之后、金融意图之前，恢复程序仍可继续已知结算；未知零费用转核查。

已接入文本、图片/embedding 共用文本结算、音频和实时语音的最终明细保存；原字段采集覆盖 OpenAI Chat JSON/SSE、Realtime、Claude JSON/SSE 及转 Responses、Responses JSON/SSE/WebSocket/压缩及转换路径、Gemini 原生/Chat/Responses 的 JSON/SSE。Chat 累计、Realtime 每个不同 response 的增量分别处理；缺失输出只估算输出，不能清空已收到的输入/缓存。明确 0 保留，估算保存计数算法版本；TTS 音频时长与字节估算明确标为 estimate。未核实原字段的其他适配器仍标 adaptor，不能宣称是真实供应商回执。新模式音频倍率结算/追加和日志使用请求捕获的倍率；实际尝试价格与原换算、工具价、音频价归属按下文契约保存。

Claude 保存原始输入、缓存读取、缓存创建总量及 5 分钟/1 小时分类；兼容补字段发生在采集之后，不把补出的字段冒充上游报告。Gemini 保存原始提示、工具输入、候选输出、思考及模态分量，输入合计包含工具输入，输出合计包含思考；合计标记归一化算法，缺失分类保留未知或估算。消费标量和原生 BillingUsage 使用相同归一化结果，防止后者在结算时覆盖估算或明确零值。零收费依据沿用原定价表达式的分类语义，不能漏掉 Claude p 中合并的缓存读取，也不能把经过验证的 Gemini 合计一概当作无依据。

缓存原量与兼容计量分开保存。供应商别名与标准字段矛盾时，原值均保留，按既有 New API 兼容逻辑计量，但标为 adaptor 和冲突算法；不能据此宣称用量已精确核实。别名单独存在且无矛盾时按实际报告采集，累计流的新值覆盖旧别名值，不把它误当成新的冲突。DeepSeek 的两个缓存字段在[官方协议](https://api-docs.deepseek.com/api/create-chat-completion/)中应相同；合成矛盾用例用于验证异常处理，不作为真实供应商回包的证据。

SSE 还区分字段是否只是途中累计量（partial）。开头报告的输出 0 保留为原证据；若后续收到输出但缺少终局用量，则按已观察输出估算，并保留途中计数作为下限。完整终局明确 0 可以作为实际回执；空的最后 usage 或缺失字段不能把早期计数升级为最终量。原事件不修改，最终快照保存本次结算实际采用的来源及估算依据。

语音转写按[实际 JSON 协议](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)采集 `usage.input_tokens/output_tokens/total_tokens` 及单数 `input_token_details` 的音频、文本分量；明确 0 保留。`usage.seconds` 是秒，可以有小数，不能冒充 token。时长回执沿用现有输入估算收费，估算来源及算法单独记录。缺失输出和断流按已收到的转写文本估算，不覆盖完整终局回执；[流式终局](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/streaming-events)由 `transcript.text.done` 确认。JSON 损坏、负量、分量与总量矛盾、混用秒与 token 均拒绝保存为可靠证据，已提交请求保留核查。JSON、SSE 均在转发之前保存报告的计量；不持久化转写内容。兼容供应商的其他字段形状仍待逐项核实。


语音合成按 [vLLM-Omni 公开兼容协议](https://github.com/vllm-project/vllm-omni/blob/main/docs/serving/speech_api.md)采集 SSE 的嵌套 `usage` 和非流式 `x-vllm-omni-*` 数量头；输入文本/参考音频、输出音频与总量分别保存，完整明确零不被估算覆盖。测试夹具是公开协议的合成回包，不声称是 OpenAI 或 vLLM 实际调用证据。缺少终局时按已解码音频字节做原有字节估算，保留途中计数下限；不把 base64 字符数、未知供应商采样率当作核实 token 或时长。`speech.audio.done` 才确认 SSE 完成，EOF 不确认；`speech.audio.error` 保留失败分类。真实二进制响应不因请求 SSE 标志而被当成 SSE。响应头在转发前保存，读取音频失败仍保留可靠回执并标记不完整。缺失文本分类的估算从输入扣除已知音频，避免重复计费；无效、重复歧义、负数、超界、分量矛盾的数量头拒绝作为依据。二进制音频仍沿原逻辑缓冲转发，原始字节流继续缓冲模式，写入阶段由通用包装记录，不声称支持边生成边转发。

零收费按实际价格依赖的字段判断：所需计量缺失则核查，不能仅凭输入、输出存在就假定缓存用量为 0；成功求值的常量 `fixed(0)` 可以正常零收费。任务零费用按表达式实际求值的 `u(...)` 分支判断：已用数值量必须有完成提取，冻结的枚举/布尔请求条件可以决定免费分支；未用量缺失不阻止明确免费。只有提交估算为零且没有完成数量时转核查，最终证据记零费用未证实，不写资金意图或释放原占用。已冻结的零价按次任务可正常零结算。免费资格与费用为零不替代现有身份校验。`Uncollected` 是参考收费与合法实收之差，代表平台未收取费用，**不等于已核实的供应商支出**；无供应商成本依据时，不能把它包装成精确上游成本。

Images 的 JSON、JSON 转 SSE、真实 SSE 均采集 `input_tokens/output_tokens` 及文本/图片/缓存分量，缺失 token 保留 unknown，不从图片 base64 字符数推算 token。[官方图片协议](https://developers.openai.com/api/reference/resources/images/methods/generate)和[流式协议](https://developers.openai.com/api/reference/resources/images/generation-streaming-events)提供基础模态结构；缓存模态是兼容接口的合成契约，不据此声称官方已报告该扩展。账单数量沿用 New API 规则：按 URL/base64 图片内容推导时标 adaptor 及算法；无有效图片或断流不能降低数量时，以原请求数量作为 estimate。没有图片内容的 completed 事件不计为一张图片。明确零仍保留，部分计数与完整终局分开；证据投影允许断流估算替代部分计数，并以部分计数为下限，完整 upstream 终局不能被估算覆盖。途中 adaptor 合计也作为估算下限，不因归一化来源而被丢弃。

价格快照同时保存请求的积分换算、当前计费模型下的所有生效工具单价及 Gemini 输入音频单价；工具价格从同一个不可变索引取得，沿用现有最长模型前缀及默认值规则，明确零不回退为新价格。新账本文本、音频、实时计价与日志使用捕获换算，文本工具附加费使用捕获单价。请求开始后修改配置不改变已有收费依据；新请求使用新配置。尝试之间的完整价格/路由版本归属继续在本轮及第 10 轮补齐。

异步任务、即时成功任务和 Midjourney 在写资金意图前保存不可变的终局参考费用及任务关联。没有 token 回执时，输入/输出 token 明确记录为 unknown，不制造报告的零。资金事务失败或意图尚未提交就退出，重试及恢复复用原证据；恢复仍检查任务确已成功，未完成任务继续交给轮询。任务展示和重新读取后的重放使用实扣 Charged，参考费用 Actual、平台未收取 Uncollected 分开。失败交接后清除内存中的旧执行资格，下次重试重新取得资格。任务表达式同时捕获提交时选中模型的数值计量单位，保存于冻结价格快照；即时完成和轮询完成的提取数量单独保存，轮询数量与成功状态一起落库。最终明细按冻结单位记录数量，插件提取标 adaptor、提交估算标 estimate，缺失量标 unknown。供应商资源积分 3.5 等合法小数原样保留，金额沿既有规则舍入；不能把供应商积分当作用户积分金额。插件提取不能证明原始供应商字段路径，本阶段不宣称已核实该来源。任务成功状态与提取数量已落库、终局证据尚未写入时，恢复器用原请求的表达式和价格快照重建最终费用；管理员后来改价不影响恢复。无法从保存内容确定费用的非表达式调整保留核查，不拿提交估算冒充实际费用。即时成功任务即使最终费用超过余额也必须保存及结算：实扣按合法资源封顶，超出部分记平台未收取费用，不能在已完成之后用追加预占不足提前丢弃结算。数值饱和在即时、轮询及恢复路径均保留管理员审计标记。Midjourney 的成功状态和按次费用已保存、终局证据未保存时，同样按任务绑定及新执行资格恢复，不再次查询上游、不用当前管理员价格。

OpenAI 兼容 Chat SSE、原生 Responses SSE、Claude Messages 及其 Chat/Responses 转换、Gemini 原生及其 Chat/Responses 转换已接入执行中预算检查：临时用量投影复用原输入依据、部分回执下限和输出估算，监测不改写原证据；工具调用及时计入原有费用，表达式和附加费沿原定价。只增长原预占，不换来源；已确认不足停止读取和转发，错误事件替代正常 DONE/协议完成事件，最终原依据按合法额度封顶结算并保存 `budget_stop`。传输扫描先看到 DONE 不会把因预算停止的部分回执冒充完整终局。求值或存储失败返回不泄露内部详情的错误，保留核查，不自动重试生成或提交收费意图。按次价格和额度充足的 token 价格保持正常完成。真实 HTTP 回归检查内容边界、实收/平台未收取、有限额 Key 与包守恒；严格矩阵要求每个数据库分别完成 reported、estimated、storage_failure、request_price、healthy_tokens。Responses 的临时预算检查不提前结束计量累加器，不把早期估算存成终局；临时图片工具计数与原工具状态隔离。Claude 保留缓存语义，Gemini 保留思考/工具分量及合计来源，转换链不另算一次费用。Gemini 预算停止在通用失败转换之前返回，不追加伪造的供应商失败。原生 Gemini 的错误封装沿用本项目现有方式，此阶段不改造 Google RPC 错误契约。后续已补齐缓冲 Responses SSE 转 JSON、语音 SSE 和原生 Realtime 预算，具体边界见下文各契约；二进制音频继续原缓冲模式，不能把这些覆盖宣称为所有供应商已精确核实。

本轮已补齐下表能力，并完成整轮审查及必要验证。已实现的采集范围不能解释为所有供应商提供了精确回执：无法核实原字段的适配器/插件保留 adaptor，缺失采购价格继续 unknown；按设计提供人工确认与修正，不虚构自动供应商补查接口。账号稳定标识及实际路由重试控制属于第 10 轮，用户页面属于第 11 轮，ClickHouse 非事务投递和完整故障/容量演练属于第 12 轮。

发送价格证据契约：初始准入 `PriceSnapshot` 保持不可变。每次上游发送前，提交标记与该尝试的实际价格依据在主库同一事务保存；相同尝试重复标记幂等，改变价格或路由后复用尝试编号拒绝发送。证据仅保存渠道 ID、分组、计费名、映射模型名、协议及可序列化价格配置，不保存凭证或请求内容。积分换算、工具价和 Gemini 音频价沿用本请求已捕获值；原生自动分组重试可改变分组倍率。最终计量关联实际尝试价格证据，恢复与核账验证关联及摘要。暂无采购价格依据时不推算供应商成本；内部账号稳定标识由第 10 轮补齐。

异步终局及终局前崩溃恢复共用 `creditSubmittedPrice`：有发送证据时读取最新实际尝试的冻结价格，历史内部请求缺少该证据时才使用原始准入快照。任务的完成数量保持原持久化数值，不读取当前管理价格重算；单位及零价依据同样使用实际提交版本。第二次尝试免费不能被初始付费规则误扣，收费组切换也不能在重启后退回原倍率。恢复日志的分组倍率和计量凭证指向同一尝试。

Responses WebSocket 预算契约（已实现）：同一连接的每个 response.create 继续独立建账。每个属于当前响应的有效事件先保留原量并更新本次累计，再按已观察数量检查原来源预算；不足时不转发当前输出或正常终局，按观察量封顶结算，发送关联本次 create 的原生错误后关闭连接与上游，不接续新请求。求值或存储失败不写收费意图，转核查并保留占用。其他 stream_id 及上次响应的迟到事件仍遵守原隔离规则。免费或固定价格不按 token 数错误阻断。客户端读写失败继续原中断规则，不把取消成功当成供应商停止计费的证据。

协议转换计量与预算契约：Chat 与 Responses 双向流转换先保存转换前的原始字段、更新本次用量并检查预算，再发送转换后的客户端事件；转换只改变呈现，不另计费用。Responses 来源复用同一个计量累加器，包含原工具/图片规则；Chat 来源保留缓存和音频明细，缺失或部分输出沿用原文本/工具估算。完整明确零不能被转换 DTO 的默认值替换为估算；缓存字段缺失不能推断为零。预算不足保留已观察参考量及平台未收取差额，不发送正常完成；求值/存储失败保留核查且不保存收费意图。HTTP 状态取决于客户端事件是否已经写出，已开始 SSE 仍以原生错误事件结束。客户端 Responses 的非流式请求经上游 Chat 返回后，同样保留原 Chat 数量来源。此项仅定义协议转换；后续缓冲、语音和原生 Realtime 的已实现范围分别见下文，其他供应商仍按实际来源标识。

转写/合成 SSE 预算契约：每个事件先保留原用量，累加已观察转写文本或已解码音频字节，再在隔离投影中补足缺失/部分数量、检查资金后转发。监测不能把早期估算写成终局。金额使用最终结算相同的文本或音频分类规则：实际有音频分类时按冻结音频倍率或表达式，其他转写输出沿原文本路径；表达式求值失败不能退回另一套价格继续生成。不足时关闭继续读取，原观察量按合法资源封顶结算并记录预算停止；不能发送 transcript.text.done / speech.audio.done。存储故障不写收费意图，保留原占用进入核查。足额及固定价格保持原完成行为。当前 byte/1000 的合成数量是原有本地估算，不能宣称供应商 token 或推断未知采样率/时长；逐项估算参数按下文契约保存。二进制音频继续原缓冲转发；原生 Realtime 预算及估算已由下文独立契约实现。

Realtime 预算契约：原生实时语音继续按一条连接的累计用量结算，已完成 response 的回执与当前未结束生成分开。每次转发生成片段前，用已完成回执加当前原生文本/音频观察量检查同一资金来源和冻结价格；完整回执覆盖该次本地估算，重复回执不得再累计。不足时当前已观察输出计入参考费用、不转发超额片段，按合法额度封顶结算，返回原生预算错误并关闭连接及上游。求值或存储故障不被普通网络关闭吞掉，不保存收费意图，保留原占用进入核查。尚未发给上游的客户端输入在资金不足时不能作为已发生费用；不能用未知采样格式伪造供应商量。观测估算及版本和完整原始回执分别留存，不把上个 response 的完整量当作当前生成的终局。已验证原生文本、PCM16 输出、已完成回执叠加未完成生成、足额完成及存储失败；客户端 conversation.item.create 在送上游前计入预算，资金不足的未发送输入不收费，conversation.item.created 确认不重复计量。逐项音频/实时估算参数按下文事件契约保存；未准入的新实时协议不宣称已验收。

缓冲 Responses SSE 转 JSON 预算契约：客户端明确要求一次性响应时，每个上游事件仍先保存原量、更新累计及检查冻结价格，但不向客户端发送部分内容。已确认不足立即结束读取并关闭上游，返回单个 JSON 错误，已观察用量通过正常结算入口按合法额度封顶；未收取部分由平台承担，不追扣。存储/求值故障返回隐藏内部信息的 JSON 错误，保留占用进入核查，不写收费意图。正常及按次价格继续返回完整 JSON，原完整零和未知量区别保持，协议转换不另计费用。预算停止不伪造正常完成。

语音估算描述契约：字节估算保存实际已解码数量、每 token 1000 字节的原规则、向上取整算法版本及计数时映射模型，不推断供应商 token、格式或时长。二进制时长估算保存解析时长、向上取整秒数规则、1000 tokens/minute；PCM 分支还保存实际采用的 24000Hz、16-bit、单声道参数。极大时长按既有安全上限计量，描述中的时长饱和有明确标记，不能当作完整原量。完整供应商回执优先，本地描述只附在 estimate 字段；输入文本分类由原输入减已知音频分类推导，独立标明算法和数量，不重复计费。

Realtime 估算事件契约：每个实际计数的文本/音频片段单独追加 estimate 阶段的原计数描述，字段使用 realtime_observed 命名空间，与供应商回执、最终连接计量分开；事件与回执共用严格递增序号，不改变累计收费。文本记录该次实际分词器/启发式配置和独立片段舍入；音频从同一次 base64 解码取得字节数、样本数、采样参数、时长和原输入/输出换算公式，保留原截断次序。采样参数是本地计量规则，不冒充已核实的供应商参数。未知格式沿原本地回退时明确 unknown_format_native_fallback，不标 upstream。客户端预算通过后才记录其待发送估算，资金不足拒绝输入不写该计数，服务器确认不再计数；生成片段先存计数再检查预算和转发。计数凭证写入失败立即停止并核查，不写收费意图。最终聚合不能附单个片段的计数描述；完整回执仍覆盖该响应的本地估算，原估算事件保留便于解释。

请求阶段记录契约：上游提交意图沿用原尝试价格凭证；追加 relay 阶段记录实际收到的 upstream_response、upstream_error、第一次 client_write_possible 及 client_write_accepted，与该尝试价格版本关联。状态码和字节数用可空字段区别未知，各事件仅保存阶段及有界数值，不存地址、内容、错误原文或凭证。写前记录 possible，返回正字节数后记录 accepted；accepted 不代表客户端读取或供应商成功。控制 ping 不计作生成输出。SDK/WS 按实际可观察边界记录，不伪造 HTTP 状态。阶段写入失败必须停止并核查，不能继续提交收费意图或自动重放生成；执行代次、已保存终局和未知状态仍受原防重规则保护。这是本轮新增证据能力，已验证通用 HTTP、SSE、二进制写入接口和原生 WebSocket 接入。写入观察只发生在本执行者仍持有账务资格且金融意图尚未提交时；已交接异步任务后的提交回执、结算后延迟发出的 WS 终局不会补造 accepted，缺失该记录表示未知。WS 终局预备发送在结算前记录 possible；实际重试与账号行为在第 10 轮验证。

图片流预算契约：真实 SSE 在各事件原量采集后、载荷转发前，按原图片计数/计价检查同一资金来源。未完成流的数量不低于本次有效请求 n，已观察有效载荷数超过 n 时采用更高数量；不能把 payload-less completed 算图片。token 定价继续使用原完整/部分字段，不从 base64 推导数量。JSON 转 SSE 已取得完整响应，在首张转发前检查完整原量。不足关闭继续读取、错误替代正常 DONE，保留原观察依据并封顶结算；求值或存储失败核查/no intent。独立预算停止标记优先于扫描器提前读到的 DONE，不能因此把未观察尾段或降低数量当作完整成功。正常、按次和 token 计价均保留现有原生规则，监测的私有倍率映射与原对象隔离。

输出凭证故障契约：故障工作器取消上游上下文，不改写主协程正在读取的 Gin 请求对象；同一停止资格只执行一次。生成写入和 flush 优先返回原凭证故障，再检查普通连接取消，防止错误被降级成通用取消。终局错误由专用渲染入口发送一次，已接受但缺分隔的上一帧先结束；普通客户端断开不升级为账务凭证故障。

### 4.17 第 10 轮：账号路由与重试边界

- 保留 New API 的渠道权重、优先级、随机/轮询和 off/prefer/strict 配置；严格绑定进一步覆盖实际凭证账号。
- 主库保存随机稳定账号 ID、非公开凭证摘要、凭证版本；凭证正文仍只由 Channel.Key 保存。Key 重排保留身份，删后重建为新身份，明确轮换入口保留身份并增版本。不能推断不同 Key 来自同一供应商账号。
- 会话绑定按认证用户、有效分组、规则与可选模型作用域隔离，值不存原文；主库仲裁并发首次绑定，缓存不是严格绑定的事实来源。严格模式不可用即停止；prefer 只在策略允许时切换并留痕。
- 每次尝试保存账号与凭证版本。已向客户端写出生成内容或提交结果未知不得自动重放；确认返回的错误状态继续现有可重试状态码规则；用户只付一次。

| `PUT /api/channel/:id/accounts/:account_id/credential` | 敏感渠道写权限；JSON 为 `credential_version` 和 `key`；事务锁定渠道，版本冲突返回 409；同更新重放返回原版本，不重复增加 |
| 原会话缓存清除接口 | 同时清除主库绑定；按规则精确清除，失败不得报告成功 |
| 原渠道编辑、禁用及删除 | 与账号选择、轮换使用同一数据库行锁；重排保留健康状态，删除退役身份，按状态删除在锁定后复核最新状态 |

接口沿用现有管理员鉴权、RBAC、访问令牌范围及 CSRF 中间件，控制器再次读取数据库中的最新状态和权限。审计只记录操作者、渠道/账号 ID 和版本。普通渠道编辑替换凭据仍是删除/新增；保留账号身份必须走轮换入口。

#### 任务与重试合同

任务私有字段增加可选 `account_id`、`credential_version`，数据库序列化不能丢弃只含这两个字段的记录。每次查询/内容下载/继续生成解析原账号当前凭据，提交时版本保持不变；批量查询按账号分组，固定查询不推进负载均衡游标。账号/渠道不可用时不换账号、不凭空写供应商失败。

严格绑定在第一次网络发送前由主库原子认领，后续选择和重试均保持该账号。会话优先模式只在未输出且已确认失败、原策略允许时切换；off 继续随机/轮询。原 HTTP 错误状态可以参与状态码策略；提交没有明确错误回执、成功后读取失败、客户端输出已开始、客户端取消、进入核查或已结算/释放的账务会话均拒绝整次重放。已有 keepalive 控制帧不伪装成生成输出。

### 4.18 第 11 轮页面契约（已实现）

- 用户钱包使用新账本查询，`GET /api/credit/account` 分别返回 API 和套餐购买用途的可用积分、预占总量及分页积分包；积分包按到期时间、创建时间、ID 排序，过期分量读取时即归入过期，不等待后台任务。未来生效、冻结及已过期资金不进入可用余额。普通用户身份来自认证上下文，不能通过 `user_id` 改查其他账户。

- 窗口显示各自状态、预占、消耗、参考用量、可用量、开始/结束时间；权益标签只显示仍有效的购买快照。以服务端时间和收到响应后的经过时间计算显示到期，并重新读取服务端，不把用户电脑时间当作权益依据。

### 4.19 第 12 轮启用与交付契约（已实现）

新安装在共享数据库持久化 `CreditNewUserAccountingVersion=1`；重复启动和其他实例不会覆盖已保存政策。首次管理员与普通创建入口在事务内读取政策，不接受客户端写入账务模式、不依赖缓存；用户、零旧余额、积分账户及来源奖励一起提交。既有开发数据库保留旧用户和模式 0，没有历史商业数据迁移功能。非法政策值失败关闭。业务用户的零金额奖励无需来源配置，正金额奖励必须具有明确期限和用途；缺失配置不发永久积分。

验收使用实际子进程在预占事务内、预占提交后、上游提交标记后、结算资金事务内、已结算后被 SIGKILL。只有有依据的状态可恢复为结算/释放；未知上游提交转核查且保留原占用。两个真实进程通过同步点竞争过期租约，恰好一个获胜；原执行者迟到拒绝，用户暂停新消费时在途仍可结算，恢复用户后原剩余额度可继续使用。

Redis 陈旧大余额、陈旧零余额和客户端连接故障不能扩大或清空数据库的合法可用积分。消费日志清理不删除核心账本、操作唯一键或投递收据；重复来源、预占、结算与日志投递保持单次效果。

SQL 日志库使用事务收据防重；ClickHouse 25.8 的非事务日志保留不可变载荷及可见核查，不假报投递成功。切换回 SQL 日志库后，管理员可按原稳定 ID 恢复，原账单和修正日志分别只投递一次。24.8 在当前既有审计 JSON 结构上实际启动失败，测试及示例改用 25.8，不声称验证了 24.8。

真实 SQLite/MySQL/PostgreSQL、独立 SQL 日志库、Redis 和 ClickHouse、三库新建/上游发布升级与两次启动、全量/race/vet/构建及 A01–A24/I01–I14 已收齐证据，见开发进度和验收映射。本轮验收不要求生产凭证、域名、证书、上线审批或生产容量承诺。用户另已明确授权验收后提交并 push 到自己的 fork；不授权生产部署。
